# Interventions before interpretations

The difference between "the employee is behind" and "the access
owner has not granted permission" is not softer wording. It changes
who needs to act. Treat the manager's draft as hypotheses about the
week, then prepare the interventions that the available facts justify.
This is a decision procedure for an actual conversation, not a
template to be filled with positive and negative talking points.

Before answering, call `read_reference` on
`references/decision-walkthroughs.md`. It contains fictional
practice packets with completed manager pages and one handoff.
Learn how the diagnosis changes an action; do not copy its names,
numbers, structure by rote, or prose.

## Lifecycle test: do we know the current state?

Separate an instruction to "prep next week" from the age of its
evidence. If the only attachment is minutes or a transcript of
a conversation already held, the statuses inside belong to the
old meeting. A deadline recorded there is not proof that the
action remains open. Return a brief handoff instead: "These are
past-meeting notes," the follow-ups with owners and recorded dates,
what is unknown now, and a request for current action states,
work measures and either person's new topics. No agenda, no
inferred delinquency, no script for private disclosures. When
up-to-date signals accompany the old record, they establish a
new week; the minutes are history only. A skip-level request or
review-cycle rating is another kind of assignment and needs
its own artifact rather than a disguised weekly agenda.

## Build an internal case for each proposed conversation

Make a private case file for each filed item: the manager's assertion;
the primary observation that supports it; the observation that
would disprove it; what decision becomes possible; and whose
authority that decision needs. Include topics sent by the report
and commitments on both sides. This is a falsification check:
the absence of a reply from another team is not evidence that the
report lost interest, while two completed side tasks are positive
evidence of ongoing engagement. Do not smuggle a manager hunch
into the output as a proven employee trait. If the records disagree,
name the unresolved difference and ask for the missing source.

Next draw a *constraint path*, not an employee score:

    promised outcome <- unfinished step <- missing prerequisite
                      <- controlling person/team <- available intervention

For a late document, ask whether providing the missing prerequisite
today would let its author proceed. If yes, label the document
blocked and put the upstream request on the manager's side. If
not, a separate employee-side impediment may remain; ask what it
is rather than deciding from the date alone. Mark completed work
as completed, unless a later independent record conflicts.
Separate productive parallel work from a blocked primary task:
both can be true, and together they refute a simple "disengaged"
story. Never invent the upstream team's ETA or imply an employee
can authorize access they do not control.

Apply a *waiting-cost test* before ordering the meeting. Count
downstream work, affected groups and shared blockers from supplied
figures. A reviewer designated the only approver for several
teams is a system choke point. Even if the manager calls it
"quick feedback, low," it needs a high-priority allocation
decision, not advice to answer faster. Explicitly explain the
priority reversal in terms of dependent work. Lay out feasible
manager levers: authorize another reviewer, redistribute a queue,
escalate a missing response, or set a checkpoint. Select only
levers supported by the packet. When the employee already proposed
the distribution, make the question "what approval do you need
to try it?" instead of restating their idea as an instruction.

Now test the *size* of each human conversation. A result with
named impact or attributable thanks can earn recognition before
the work decisions; a vague wish to "say something nice" cannot.
A first, repaired incident warrants one feedback question about
its consequence and a safeguard. Two genuinely comparable
events can establish a pattern; if the report has already
identified the driver, coaching should co-design the earliest
signal of that driver, not demand a confession of lateness.
Use the observed event or measured change in the question.
An employee-raised growth interest must get a question in the
room, even when the manager files it as "if time"; separate a
later formal level decision from the conversation about direction.

One concern may split into two decisions. A worker may be right
that an upstream approval blocks a deliverable but wrong to
apply pressure to a whole public channel. Read every relevant
message, including any later polite private request. Put
authority to solve the dependency with the manager, and retain
one narrow question about venue if the public message supports
it. Neither dismiss the real block as an attitude issue nor
pretend the venue cannot be discussed because the block was
real. A single awkward moment is not a general coaching plan.

Finally test the *room*. A weekly one-on-one can hold a work
decision, a bounded feedback question, and an employee's
career direction. It is not where a pay determination, personal
health inquiry, formal complaint or organization-wide policy
ruling gets scripted. State the minimum needed to arrange the
appropriate separate conversation and its organizer; leave
sensitive talking points unwritten. A thin packet can still
support an honest status question and a confirmation of a
secondhand career interest. It cannot support invented
achievement, performance claims, dates or aspirations.

## Recheck the measurements

Derived context matters when it changes the interpretation:
write both operands and the result, e.g. `9 of 12 tasks done =
75%`, `68% to 73% = +5 percentage points`, `13 completions versus
10 before = 3 more (30% relative)`. Do not interchange percentage
points with relative percent change. Where two periods are given,
compare them; distinguish current throughput from blocked work on
another route. Count actions completed and still held when the log
supports it. Compare dates to the meeting only when that date is
actually known. No inferred owners, denominators, deadlines or
recognition. For a sparse packet, say which records should be
pulled before the meeting rather than manufacturing a metric.

## Hand the manager a usable page

The trace above is private reasoning, not the deliverable. Open
with report and role, then a short synthesis of what changed, what
is held and who can move it; include worked figures that matter.
Arrange only the conversations the evidence earns. Use natural
topic headings and ordinary labels such as recognition, work
decision, feedback, coaching and development. Each item gets the
deciding signal and an actual line or question the manager could
use, no more than three sentences of talking points. An anchored
question names the thread, figure, incident or interest; avoid
generic "how are things?" in a coaching or growth slot. Explain
one corrected priority or category briefly where it changes the
meeting; don't build an internal classification table for the
manager to decode. End with the manager's own commitments, and
include a separate-venue note only if the packet calls for one.
An evidence-poor week should produce a short page, not a fixed
quota of sections.

Final check before sending: every proposed topic has a place,
is combined with another named item, or is absent for a stated
reason; the employee did not inherit a manager-owned blocker;
questions are specific; all numbers re-compute from the input;
private matters have no script. If the packet was only historical
notes, none of this page should appear.
