# First Question — every item is a question before it is an answer

This skill reads the input the way a skeptic reads it: each item is not a fact
to file, it is a question the decision needs answered. Every item becomes
its sharpest question; each question is answered only from evidence actually
in the record; whatever the record cannot answer is named openly. The output
is a verdict a reviewer can re-derive — not a smooth summary that hides the
doubts.

## The questioning pass

**Pass 1 — Frame the real question.** Write what this prep serves and
what must be true for it: the report, the meeting date, and the question
the whole input must answer. Items only matter against that
frame — a frightening item that the frame does not depend on is still a
detail, and a quiet item the frame cannot survive without is the whole
decision.

**Pass 2 — Sharpen each item into its question.** A document is never just
a document: a press release is "is this claim independently true?"; a
missing record is "does the record exist?"; an unnamed source is "can
anyone stand behind this?" — always no, whatever the topic; a name one
letter off is "is this the same party?" — unanswered until identity
checks. Write the question each item actually raises before touching its
content.

**Pass 3 — Is the question still open?** This is the pass most analyses
skip, and where they die. An item the record marks answered, closed, or
filed STAYS answered — unless ANOTHER artifact states a present fact the
answer cannot coexist with (a process it says is still running, a notice
already served, a cure nobody can document). The item's own text never
reopens it: the finding's words describe what the author weighed when
closing it. Suspicion is not a contradiction; a scary sentence inside a
closed item is still a closed item. When a later artifact and the label
genuinely disagree, say so explicitly ("marked answered; the record shows
X; treated as open") — never reopen silently.

*What this pass forecloses:* if every question is closed, nothing later can
legitimately change the call — and reopening one anyway is its own error.

**Pass 4 — Answer only what the record supports.** When artifacts
disagree, name the artifact that decides and quote the tiebreaker. An
answer the record does not contain is written as an open question with the
named record that would settle it — never filled with a plausible guess.
Derived arithmetic is an answer; an invented input is not.

## Which questions can hold the call

Only questions the input itself filed — a topic the manager's draft agenda
or the report's own submission actually filed, nothing the brief invents —
can hold back the decision, and only while open. An
open question on a lower tier never holds anything: it is answered with a
named disposition — the record, the owner, the timing — and the call
proceeds. A blocker = filed top-tier AND still open; nothing else
qualifies, however urgent it reads. Tier and scariness are different axes.

## The numbers question

Ask the same skeptic's questions of every figure:

- **Is every derived figure computed?** The input's raw numbers are raw
  material — point changes, completion rates, blocked counts, scope deltas
  are questions to answer, not figures to copy. Show each bridge: the
  reported figures, the operation, the derived result.
- **Blocked or delinquent?** An overdue item held by an upstream
  dependency is blocked, not neglected — say which, and name the blocker.
  An external dependency is a question for the manager, not a mark against
  the report.
- **Is each due date measured against the meeting date?** An item due the
  day before the meeting is a different question than the same item due
  next month — compute the gap, never copy the date.
- **Is every pair enumerated?** Before the header is written, list every
  comparable pair the input offers — each raw figure against the figure
  it belongs to — so no derivable number is skipped.
- **Is the arithmetic reproducible?** Write every product expanded —
  `3 of 8 = 37.5%`, `61 → 74 = +13 (+21%)` — so the header's figures can
  be re-derived from the input alone.

## The verdict

Every filed item gets exactly one disposition — four shapes, never fewer
than the record allows:

- **Kept**: the signals hold the item as filed — it gets its anchored
  question. When the record allows it, the item stands — demoting it is
  as wrong as routing over an open question.
- **Kept-on-conditions**: the item stands but reshaped — a coaching label
  the signals soften to a question, a status that is really a blocker for
  the manager to clear. Keep this middle call; do not collapse it into
  either neighbor.
- **Routed**: the item is real but belongs to another venue — a sensitive
  topic, a dedicated conversation, an escalation the manager owns. It gets
  a named venue, never talking points.
- **Dropped**: nothing in the record warrants the item — the recognition
  with no signal behind it, the padding topic. Its absence is itself a
  finding worth stating.

A condition is itself a question with a named answerer: which record cures
it, who produces it, by when — and what follows if it does not arrive.
"Investigate further" is not a condition.

## The reply

- Line 1: the week's posture, the one deciding item, and the key figure —
  then the header: report, role, and every derivable figure computed —
  point changes, completion rates, blocked counts — never restated raw.
- The agenda table: every filed item with the manager's label, what the
  signals say, its disposition (kept / kept-on-conditions / routed /
  dropped), and the anchor that decides it — before any prose.
- Talking points: questions only, each tethered to a named signal — a
  thread, ticket, figure, or person — at most three sentences apiece;
  statements and unanchored questions do not belong.
- Routing notes: sensitive items named with their correct venue and zero
  talking points; missing inputs listed as evidence gaps; the manager's
  own open items surfaced.
- Recognition appears only when a signal warrants it — named anchor, or
  absent.
- Every quantity written as reproducible arithmetic, endpoints divided back.
- Where the input is silent on a quantity, deadline, or owner, say so
  plainly and make obtaining it a named evidence gap. Silence is a
  finding, not an invitation to invent.
- The brief reads as a practitioner's artifact, not the method that made
  it: section headings name the deliverable ("Context", "Agenda",
  "Talking points", "Routing") and never restate the rules inside them;
  the table already carries each item's call, so no verdict summary or
  self-audit trails the brief; column calls use the words a manager
  would say — "status", "recognition", "route out" — not the method's
  own jargon.
- Never reuse one sentence frame across items — each item gets the words
  its own facts need.
- One invented worked example lives in references/weekly-prep-brief.md —
  showing this contract end-to-end on invented cases, including the
  alternate branches on the same input: the item the label mislabels, the
  sensitive item routed out, and the thin-input week with gaps named.
  Read it once with read_reference before writing; carry its shape and
  checks, never its sentences.
