# 週次1-on-1ブリーフの作り方 — 問いと答えで読む要約

**何を作るのか。** 上司が会議に持って入る一枚のブリーフ。350〜700語。文脈の見出し、分類済みの議題、根拠付きの論点、そして別の場に回す保留事項。

**最初に確かめることは。** それが本当に「これから行う部下との1-on-1」の準備依頼かどうか。終わった会議の記録、上位者との面談準備、評価の下書き、チーム会議の議題なら、ブリーフは作らず、150語以内で案内する。何が届いたのか、どの成果物にあたるのか、1-on-1ブリーフに必要なもの(今週の議題、未完了アクションの状況、数字やスレッド)。記録中のアクションは担当・期限・状況未確認で一行ずつ引き継ぎ、私的な事柄は「個別の場で」とだけ書く。「次回の準備をして」と頼まれていても、過去の会議記録は今週のシグナルにはならない。

**上司の議題案をどう扱うか。** 仮説として扱う。先にシグナルを全部読む。Slackの抜粋、アクション項目(上司自身の分も)、数字、本人が出した話題、上司のメモ。そのうえで、議題案の一項目ずつを証拠と照らす。ブロックされている人に貼られた「態度」のラベルは、他チーム待ちのエスカレーションであることが多く、状況項目になる。「意欲が落ちた」というラベルは、催促し、迂回し、別の成果を出している記録と矛盾することがある。褒めたいが何をかは言えない場合、同僚や関係者の言葉、数字を伴う成果、品質への言及のある完了項目が入力のどこかにあればそれを使い、なければ冒頭の称賛を省いて、その旨を一文で書く。

**タグはいくつか。** 五つ、各項目に一つ。称賛(上司の印象ではない具体的な肯定シグナル。一件まで、先頭)。状況(進捗とブロック。上司自身の期限超過も)。短いフィードバック(一回の具体的な出来事、修正点が明確、パターンなし。三文以内、修正で締める)。コーチング(二回以上現れるパターン、または本人の要望。一つの問題についての複数のメッセージは一つの問題であってパターンではない)。キャリア(成長、等級、昇進、メンター、担当範囲。本人が持ち出したら本格的な枠)。

**論点はどう書くか。** 括弧で根拠を示す(チャンネルと曜日、表、アクション項目、本人の話題)。一項目三文まで。コーチングとキャリアは必ず開いた質問で、根拠から育てる。どの部下にも当てはまる質問は書き直す。根拠が一つもない項目は、入力中の最も強いシグナル、それもなければ上司の議題の一行を引用して錨にする。一つのシグナルは一つの項目にしか使わない。

**保留事項には何を入れるか。** 1-on-1で決められないこと。報酬、健康や配慮、昇進の決定そのもの(キャリブレーションの場)、第三者が絡むプロセスの話、数日以上放置された他チームのブロック(上司同士の会話)、上司が負っているレビュー。各行は話題と場と設定者。該当がなければ一行でそう書く。

**見出しの数字は。** 入力が与える対(見積りと実績、前後、計画と実績、今回と平均)を一度ずつ導き、根拠の数字と出所を添える。入力にない数字からは何も導かない。参考例の週の数字をこの週に持ち込んだら、それは捏造である。他チームのブロックが数日以上続いている、または上司自身の期限超過がある場合、見出しの最後に「会議の前に:」として上司がすることを一行書く。

**順序は。** 称賛があれば一番、次にブロックや期限のある状況、短いフィードバック、コーチング、キャリア、最後に保留事項。項目は根拠が支える四〜七。返答はタイトル行から始まり、前置きも後書きもない。
