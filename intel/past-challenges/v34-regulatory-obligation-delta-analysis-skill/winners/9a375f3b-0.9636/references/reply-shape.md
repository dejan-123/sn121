# Reply shape

Write for a reviewer who will check each row against the two texts; use the instrument's short name and edition names as the input gives them.

## Worked example (invented instrument, unrelated field)

The papers: a fictional Pleasure Balloon Flight Code (PBFC) of the Tarnholm Aviation Office, Issue 2 (Rules 1–8) against Issue 3 (Rules 1–9), with Office Advisory 7/26, which calls every amendment a clarification and says the Rule 2 items were already required by Office Circular 3/24. The whole reply:

## PBFC Issue 2 → Issue 3: orientation

This delta compares PBFC Issue 2 (Rules 1–8, prior text) with PBFC Issue 3 (Rules 1–9, new text). Office Advisory 7/26 was provided and describes the amendments as clarifications of existing practice; it is read as evidence of the Office's intent, not as controlling, and each clause pair is read on its own wording. Changed: Rule 1 (new class of operator), Rule 2 (general duty spelt out; the Advisory ties the items to Circular 3/24), Rule 3 (new 20-minute re-measurement cycle, an operation), Rule 4(i) (new scenario in the briefing), Rule 4(ii) (new record item), Rule 4(iii) (new sub-item; its link to the older briefing standard is open for review), Rule 5 (14 → 7 days, tighter), Rule 6 (20 → 40 passengers, looser), Rule 8 (inserted, so prior Rule 8 is now Rule 9). Identical: Rule 7 and Rule 9.

## PBFC: delta table

| clause-ref | change-type | prior-text summary | new-text summary | action-trigger | notes |
|---|---|---|---|---|---|
| Rule 1 | scope expansion | Applies to operators of passenger balloon flights launched in the Tarnholm Reserve | Adds "operators of tethered balloon rides" to the persons bound | Yes | "Operators of tethered balloon rides" is a new class in the scope list. A tethered-ride operator meeting Issue 2 was bound by nothing in this Code, so the Advisory's "clarification" label cannot hold; Rules 2–9 keep their wording but now reach that class through this Rule. |

**Review-flagged clauses:**
- **Rule 4(iii):** Did the Issue 2 Rule 4(i) duty to brief passengers already require a briefing in a language the passenger understands? If yes → clarification / restatement, trigger No; if no → net-new obligation, trigger Yes.

**Notes for downstream:** Rule 8 (clearance before lift-off, Yes), Rule 1 (tethered-ride operators now bound, Yes) and Rule 3 (20-minute wind re-measurement, Yes) come first; Rule 5's 7-day window and the Rule 4(i) fire briefing need procedures updated now; Rules 2 and 4(ii) only extend existing checks and records on paper. The renumbering of Rule 8 to 9 changes internal cross-references only.

Had the papers been only PBFC Issue 3 with no prior text, the whole reply would be:

## PBFC Issue 3: delta not possible

**Stop: the prior text is missing.**

A delta needs both editions, and only PBFC Issue 3 (Rules 1–9) was supplied. Reconstructing Issue 2 from memory or another authority's balloon code would be unsafe: editions that read almost alike can still move a deadline, a trigger or a class of persons, and a table built on a guessed prior text would mislabel exactly those shifts.

To proceed, please provide: the PBFC edition that Issue 3 supersedes (Issue 2, Rules 1–8), pasted in full.

## Shape

1. `## [Instrument] [prior edition] → [new edition]: orientation`, with `Changed:` and `Identical:` as above; an identical clause takes `no substantive change` whatever a deleted exemption or wider scope clause now does to its reach.
2. `## [Instrument]: delta table`: the six columns above, one row per clause of the new text in its order, printed sub-items on their own rows, deleted prior clauses last; unchanged rows read summary | `Identical` | `No` | `Wording unchanged.`, with `Identical; renumbered from [old ref] after the insertion of [new ref]` (or `after the deletion of prior [ref]`) where the number moved.
3. `## [Instrument]: summary`: all six labels in the order above; each cell lists the refs, then `= ` and their number, or `0`.
4. `**Review-flagged clauses:** None.` or one bullet per Review row in the form above.
5. `**Notes for downstream:**` one to three sentences on which rows come first and why, in this instrument's own terms, and what any renumbering means operationally; different for every instrument, nothing after it.

Check before writing: a shorter period or lower trigger is `scope expansion`, `Yes`, and a longer period or higher trigger is `obligation withdrawn / relaxed`, `No`; a new class, a new scenario in a duty's object, a deleted exemption or a clause rewritten to name the new class is `scope expansion`, `Yes`, whatever the summary says; untouched wording stays `no substantive change`; an enumeration the summary ties to a named instrument of the same regulator is `clarification / restatement`, `Yes-doc`; a new cycle, clearance or verb is `net-new obligation`, `Yes`; an added record item is `net-new obligation`, `Yes-doc`; every clause, sub-item and deleted clause has a row, the counts equal the rows, every Review row has a bullet, and with a missing edition there is no table.

Your reply now begins with `## ` followed by the instrument's short name and editions, with no sentence before it.
