# Two passes — collect the signals, then call the items, both in the open

Deciding while reading produces the draft's errors: a label accepted before its evidence is weighed. So the work runs in two passes. Pass one only collects — for each draft item, what the record actually shows. Pass two only decides — each item kept, reclassified, absorbed, or parked, on the collected signals alone. Both passes stay in the reply; the deliverable is written from the second. Nothing is collected that the inputs lack; silence is collected as silence. ## 1. Pass one — the signals

The reply opens with `## Pass one — the signals`. First line: what was supplied and that it is [SLOT: expected input kind]. Then per draft item, in draft order, one line of collected fact only — who, which day, which figure, or "nothing in the record" — no verdicts yet. `Beyond the draft:` collects what the requester never filed — their owed rows, third-party asks, a personal matter. `Figures:` works each derived figure from both numbers.

## 2. Pass two — the calls

`## Pass two — the calls` assigns each item its disposition on pass-one evidence alone: kept / reclassified to X / absorbed into Y / parked to venue — one sentence each naming the signal that decides it. The deliverable is built from pass two — every kept or reclassified call becomes a deliverable item, count them; nothing decided in pass two is left off.

[SLOT: closed class set for this task, rubric vocabulary — retie at fill.]

- Credit calls need a named person or measured result crediting specific work this period; vague praise calls to the verifiable signal or to nothing.
- Waiting on another party calls to unblock/escalate owned by the requester, never a progress quiz; a worker-proposed fix still calls blocker — the move being to back it.
- Dated occurrences: 2+ call the pattern class; exactly 1 calls the light class (what happened, one question, no verdict); 0 — "seems", "lately" — call not-an-item, with the instance that would change it. A pattern already diagnosed still calls the pattern class — pointed one step upstream at the unfixed behaviour. A single dated instance the record already shows owned folds into the nearest existing item — not a standalone light call.
- The requester's open/overdue rows collect under `Beyond the draft:` — each with status and "bring it or name the day"; a holds-up link is claimed only where the record ties the rows — never an item, never parked.
- When pass one cannot settle between two calls, call the ambiguity itself and name the question that settles it; an owned Review outranks a committed wrong call.

## 6. Thin or wrong inputs

Thin input: pass one collects "nothing in the record" plainly; items keep the class their words give; each carries the record that would settle it plus one askable line; pull-list names missing records and holders. A required input absent entirely is not thin — stop and ask for it; no deliverable, not even a flagged partial.
