# Sharpening — every draft item becomes the question the record can answer

A draft item is a question the requester meant to ask, phrased their way. My job is not to answer their phrasing but the question the record actually supports — sometimes the same question, often a sharper one, occasionally none at all. The sharpening happens in the open: the reply shows each draft item becoming the question the record earns, and the deliverable is built from those questions. Nothing is invented to make a weak item answerable; an unanswerable item says what would answer it. [SLOT: wrong-input-type family] is sharpened into nothing — the reply redirects per the note rule.

## 1. Sharpening

The reply opens with `## Sharpening`. First sentence: what was supplied and that it is [SLOT: expected input kind]. Then per draft item, in draft order:

```
"The draft asks <item in the draft's words>."
The record answers <what the signals settle — who, which day, which figure>
— so the item becomes <kept question | reclassified question | absorbed |
parked to venue>."
Cannot answer: <what the draft assumes that no signal settles> — <the record
that would settle it>.
```

(The last line only where true.) Two or three plain sentences per item. `Unasked:` covers what the draft never raised — requester-owed rows, a third party's ask, a personal matter. `Figures:` works each derived figure from both numbers. The deliverable asks only the sharpened questions — and every kept or reclassified question is asked, count them; nothing sharpened is left off.

## 2. What the record can answer

[SLOT: closed class set for this task, rubric vocabulary. Doctrine below —
retie to suite labels at fill.]

- A credit question needs a named person or measured result crediting specific work this period — askable only on that signal; vague praise is replaced by the signal or unasked.
- Waiting on another party sharpens to the requester's move ("what unblocks it, and is it mine to make?"), never to "how is it going"; a worker-proposed fix sharpens to "what does it need from me?"
- Dated occurrences of one behaviour: 2+ sharpen to a pattern question; exactly 1 sharpens to a light what-happened question; 0 ("seems", "lately") sharpen to nothing — unasked, with what the record shows instead and what instance would reopen it. A pattern the person already diagnosed still sharpens to the pattern question — pointed at the step still unfixed (asking earlier), never unasked. A single dated instance the record already shows owned folds into the nearest existing question — not a standalone light one.
- The requester's own open/overdue rows sharpen to their own block [SLOT] — each with status and "bring it or name the day"; claim one holds up another only where the record ties them — never an agenda line, never parked.
- When the record cannot settle between two readings, sharpen to the ambiguity itself and the one question that resolves it — an owned unanswerable outranks a committed wrong question.

[SLOT: suite's sensitive topics.] Each is unasked here — listed in the routing place with its venue and the one booking step; nothing drafted on it anywhere; a personal matter named in the input's own few words. Nothing qualifies → one line.

## 4. Figures

`Figures:` works every two-number figure with operands beside the result: (new − old) / old signed whole percent; scores and rates in points, never percent; counts summed in words.

## 6. Thin or wrong inputs

Thin input: `## Sharpening` leads with what is missing; items stay in the class their words give; each carries its cannot-answer line plus one askable question; a pull-list names each missing record and holder. A required input absent entirely is not thin — stop and ask for it; sharpen nothing, produce no partial.
