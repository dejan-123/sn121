# The sign-off — each draft item is cleared, held, or rerouted on the record

Every draft item is reviewed before the deliverable is written: cleared means the record backs the item as labelled, held means the record does not support keeping it in this form, rerouted means it belongs to another venue or another item. The review stays in the reply — the sign-off sheet is what makes the calls checkable instead of asserted. Items are only cleared on what the inputs state; silence is recorded as silence. [SLOT: wrong-input-type family] is never cleared — the reply redirects per the note rule.

## 1. The sign-off sheet

The reply opens with `## Sign-off`. First line: what was supplied and that it is [SLOT: expected input kind]. Then one row per draft item, in draft order:

```
<item in the draft's words> — CLEARED | HELD → <what it becomes> |
REROUTED → <venue>: <basis — who, which day, which figure; or "no record:
<what would clear it>">.
```

`Not reviewed:` covers what the draft never filed — requester-owed rows, third-party asks, a personal matter. `Figures:` works each derived figure from both numbers. The deliverable is written from the cleared and held items — every one of them appears in it, count them; nothing reviewed is left off.

## 2. The review rules

[SLOT: closed class set for this task, rubric vocabulary — retie at fill.]

- A credit item clears only on a named person or measured result crediting specific work this period; vague praise holds — to the verifiable signal or to nothing.
- Waiting on another party holds as unblock/escalate owned by the requester — the move, not a progress quiz; a worker-proposed fix still holds as unblock — the move being to back it.
- Dated occurrences of one behaviour: 2+ clear the pattern class; exactly 1 holds at the light class (what happened, one question, no verdict); 0 — "seems", "lately" — held off entirely, with the record's read and the instance that would clear it. A pattern already diagnosed still clears the pattern class — held one step upstream at the unfixed behaviour. A single dated instance the record already shows owned folds into the nearest existing item — not a standalone light hold.
- The requester's open/overdue rows review under `Not reviewed:` — each with status and "bring it or name the day"; a holds-up link is claimed only where the record ties the rows — never an item, never rerouted to a venue.
- When the record cannot settle between two reviews, hold for the ambiguity itself and name the one question that clears it; an owned hold outranks a committed wrong sign-off.

## 3. Rerouted items

[SLOT: suite's sensitive topics.] Each reroutes to its venue with the one booking step; nothing drafted anywhere; a personal matter in the input's own few words. Nothing qualifies → one line.

## 4. Figures

`Figures:` shows every two-number figure with operands beside the result: (new − old) / old signed whole percent; scores and rates in points; counts in words.

## 6. Thin or wrong inputs

Thin input: `## Sign-off` records the missing evidence first; items hold at the class their words give; each names the record that would clear it plus one askable line; pull-list names missing records and holders. A required input absent entirely is not thin — stop and ask for it; nothing is cleared, no partial produced.
