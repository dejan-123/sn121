# templates/v39 — the eight skeletons (winner-shape, pre-drop)

Written 2026-11-18. Basis: `logs/STRATEGY-HISTORY.md` (the plan) and
`logs/FIELD-NOTES-ARCHIVE.md` (the evidence). These skeletons copy the
.966 winner's ARCHITECTURE — visible working, then deliverable, then why —
with eight structurally distinct organizing units for similarity distance.

## What is identical across all eight (the doctrine — never varies)

- Inputs are claims; the record decides. Read the record before the draft.
- Every input item gets **keep / reclassify / absorb / park** — decided and
  shown per item BEFORE the deliverable is written.
- Evidence thresholds: named person or measured result required for credit
  items; 2+ dated instances for pattern items; single dated instance = light
  touch only; zero instances ("seems", "lately") = not an item at all.
- External dependency = unblock/escalation owned by the requester, never
  report-owned criticism.
- Requester-owed items surfaced (their own open/overdue rows).
- Sensitive topics (pay, health, family, formal performance, named-colleague
  friction) → another venue, named in the input's own few words, ZERO talking
  points.
- **A reclassified item never leaves the output** — it stays under its earned
  class. Only two things leave: zero-signal perceptions and venue-routed items.
- **The kept set IS the deliverable** — every kept/reclassified item lands in
  the output, count them; an item read in is never silently dropped between
  the working and the deliverable (S-007/S-008 defect, fixed 2026-11-18).
- **A self-diagnosed pattern keeps its class** — 2+ dated instances already
  explained by the person still earn the pattern item, aimed one step
  upstream at the unfixed behaviour (v38 S-009 truth).
- **An already-owned single instance folds in** — one dated moment the record
  shows committed/fixed rides inside the nearest existing item; it is not a
  standalone light item (v38 S-010 truth).
- **Requester-owed links are conditional** — each owed row carries status and
  "bring it or name the day"; claim it holds something up only where the
  record ties the two rows.
- **Routing is absolute** — a venue-routed item never reaches the deliverable:
  no item, no talking point, no question, no mention under a neutral label.
- **Missing required input → stop and ask** — a required piece absent entirely
  is not "thin": produce nothing, not even a flagged partial (v34 rehearsal:
  the partial table IS the planted trap).
- **Artefact-type check runs first** — if the input isn't the artefact kind the
  criteria apply to (a notice/narrative with no operative clauses), the
  verdict is the review label + one triage row; fabricating criteria is the
  trap (v33 S-2 — the only miss in a 9/10 run).
- **Unresolvable → owned Review + the one question that settles it** — but ONLY
  when the ambiguity decides the top-line verdict; a peripheral ambiguity
  beside a clean kill is the "ambiguity as hedge" anti-pattern — commit to
  the kill (v34 S-1 Art4c; v33 S-4).
- The requester's own raised topic gets protected placement — pin its position
  in the contract slot (v38 truth: it can precede even blocker items).
- Figures shown with operands; stated absences reported as absences; nothing
  fabricated.
- Wrong-input-type → short redirect artifact (≤150–180w), NO deliverable at
  all — name the family concretely at fill time (retrospective record: notes,
  minutes, transcript, export of a meeting already held, report on a
  finished period). Carried items keep stated owners/dates as background.
- Complete short reply > truncated long one; hard length budget.
- **Worked examples set the real behavior, rules only describe it** — example
  ordering/format must match the contract exactly (mimicry > rules, verified
  on the v38 S-008 agenda-order miss). No example fact (name, item, figure)
  may ever appear in a real reply — state that in SKILL.md.
- **dataset_derived guardrail:** the example's SCENARIO STRUCTURE must not
  mirror any suite input — same archetype with renamed entities still trips
  the gate. Invent the situation shape, not just the names.

## The enumeration gate — per scenario, BEFORE the call

The blind v34 rehearsal missed 4/10 plants with every rule already known —
checks skipped under time pressure, not knowledge gaps. Run this gate on each
scenario; no call is final until its row is answered:

1. **INPUTS** — every required input present? Missing → STOP-and-ask,
   produce nothing, not even tentative.
2. **MAP** — renumbering? One no-change row, never delete+add.
3. **TIER** — new duty/trigger/scope, or only new content inside an existing
   duty? Content-only → documentation tier.
4. **COVERAGE** — practice already covered by prior standard or in-text
   guidance → clarification; external cover-note framework ≠ coverage.
5. **DIRECTION** — threshold changed? Tighter=expansion, looser=withdrawn.
6. **RESOLVABLE** — texts can't settle it → Review + specific question.
7. **ABSENCE** — is the scored answer "nothing"? Empty decisions set,
   stop-and-ask, flag-only verdict → declare it EXPLICITLY with rationale.
   Mirror: when a call IS met, still flag measurement gaps, stale updates,
   owner-derived figures, cadence anomalies. (v29 re-drill: both partials
   were undeclared absences; v34 S-005 same family — 3 occurrences.)

## Delta/change-task rulings (v34 rehearsal misses, 2026-11-18)

- **Content tier vs obligation tier** — expanded CONTENT inside an existing
  obligation (more items to submit, more covered scenarios, new recorded
  fields) = documentation tier, not substantive — unless the trigger, scope,
  or duty itself is new. "New verb → net-new" is the planted trap.
- **Coverage, not keywords** — a general standard already covering the
  practice → clarification even without a named cross-reference; guidance
  cited IN the text or note = clarification; an EXTERNAL framework named
  only in the cover note does NOT downgrade (v34 S-003 vs S-006).
- **Missing a required input → STOP.** Produce nothing — not even a
  tentative deliverable. Ask for the specific missing artifact plus one
  sentence on why reconstructing it misleads.
- **Threshold changes carry direction labels** — tighter → expansion/Yes;
  looser → withdrawn-relaxed/No. Never call a relaxation "substantive."
- **Unresolved → Review + a specific question** beats a committed wrong
  call. Apply it; knowing it is not enough.
